# 细节密度配方：把「好看」写成可比较的画面事实

## 这份文件解决什么

`common-recipe.md` 管八段式的**顺序与信息保真**，本文件管八段式里最容易写空的一段：
**主体到底写多细、按什么层次写、用什么词写**。它回答三个问题：

1. 同一张板，骨架级和定妆级分别长什么样，什么时候用哪一级；
2. 人物、服装、场景、道具各自的细节按什么层次展开，每层只答一个问题；
3. 哪些词能写、哪些词是套话、哪些词只能出现在尾部一句里。

它不改 `IMG-02`（识别优先于质量词），而是把 `IMG-02` 的「可比较的可见事实」展开成
可执行的层与词。细节密度是 `craft_default`：创作者可按平台实测结果加严或放宽。

## 一、三层密度

密度不按字数衡量，按**每层有几个可比较细节**衡量。三层共用同一顺序，只增减每层的句数。

| 级别 | 用在哪 | 每层细节数 | 中文正文参考长度 |
|---|---|---|---|
| 骨架级 | 远景识别、群演、快速提案、草图方向 | 每层 0~1 个，只保留区分性锚点 | 120~200 字 |
| 标准级 | 默认的人物/地点/道具板 | 每层 1~2 个 | 250~400 字 |
| 定妆级 | 主角定妆、跨集复用、需要「一眼认出同一个人」 | 每层 3~6 个，逐件写到材质与五金 | 450~800 字，多视图可到 900~1200 字 |

判断用哪一级，看这张图要承担什么：**只要求「像这个角色」用标准级；要求「后续每一镜都靠它锁脸、
锁服装」才上定妆级**。定妆级不是默认答案，写满了却不服务识别，等于给模型增加漂移机会。

细节预算的另一条：**多视图里身份层只写一遍**，再用一致性句要求其余视图复制；不要给每个视图
各写一遍脸和衣服——重复描述会互相打架，是四视图换脸的主要原因之一。

## 二、人物板的十一层描述栈

顺序固定。模型对前置内容权重更高，所以「是什么图、几个人、怎么排」永远在最前，
「不许出现什么」永远在最后。

| 层 | 只回答一个问题 | 必须写 | 可省略 | 不要写在这层 |
|---|---|---|---|---|
| L0 用途与版式 | 这是什么图、几个视图、怎么排 | 图种＋视图数量＋左右分区＋画幅 | 视图占比（骨架级可省） | 剧情、情绪表演 |
| L1 风格与渲染通道 | 走哪条渲染管线 | 3D半写实／写实摄影／2D；PBR、SSS、布料与发丝处理 | 渲染词（2D 平涂时删） | 平台参数、权重语法 |
| L2 构图几何 | 每块画面装什么 | 画幅比例、左区内容与占比、右区视图顺序、视平线、裁切红线 | 具体百分比 | 角色外观 |
| L3 身份骨相 | 凭什么认出这张脸 | 脸型→额头→面中/颧骨→下颌线→下巴→整体比例 | 次要骨相 | 妆、发、衣 |
| L4 五官 | 眼鼻唇眉各自什么样 | 眼型与眼尾、双眼皮、睫毛、瞳色与通透度、眼妆晕染；鼻梁鼻尖；唇形唇色闭合；眉形浓淡 | 单项可省，但眼与唇至少各一句 | 情绪表演、剧情 |
| L5 皮肤与妆面 | 表面是什么质感 | 肤色（冷暖＋深浅）、质地、腮红/修容位置 | 妆面（素颜角色可省） | 塑料感、真人骨相等禁止项（放 L11） |
| L6 发型 | 头发怎么长、怎么梳 | 发色、颅顶、分缝、刘海、鬓角碎发、发量、长度、发尾、光泽、发丝可辨度 | 局部发饰（属 L7） | 帽子（属 L7） |
| L7 配饰 | 戴什么、在哪、什么材质 | 位置＋材质＋尺度＋与服装的关系 | 无配饰时写「不佩戴任何配饰」 | 手持剧情道具 |
| L8 服装 | 从上到下穿了什么 | 逐件：内搭→外搭→下装→袜→鞋；每件写版型、领口、袖口、材质纹理、五金、颜色、穿法 | 次要配饰 | 尺度与体态（属 L9） |
| L9 体态与手部 | 身体比例与姿态 | 身高比例、肩宽腰窄、腿长、站姿、手指、脚与鞋底是否完整 | 体态（远景板可省） | 表演动作、剧情走位 |
| L10 光与背景 | 在哪拍、怎么打光 | 主光方向、辅光、轮廓光、背景色与渐变、地面衔接 | 环境光（外景板换成天光） | 气氛形容词 |
| L11 一致性与排除 | 什么绝对不能变、不能出现 | 同一人物＋逐项不得漂移清单；按失败模式分组的禁止项 | — | 新的外观要求 |

L8 是密度最容易塌的一层。写法：**一件一句，句内按「版型—结构—材质—五金—颜色」排**，例如
「外搭浅奶油黄短款针织背心，版型合身，前襟小纽扣，针织纹理清晰，露出少量腰腹」。
不要写「时尚甜美上衣」——那是标签，不是可复现的结构。

L11 的一致性句建议三段式：①「四个视图属于同一人物」；②逐项点名不得变化的类别（五官、发型、
妆容、服饰、配饰、身材比例）；③「不得换脸或改变设计」。第②段要照抄本项目实际会漂移的类别，
不要每次照搬同一串。

## 三、受控词表

同一项目内，**同一角色、同一件衣服、同一种光，反复用同一组词**，不要每次换近义写法。
一致性靠复述同一词组建立，不靠形容词变化。

| 维度 | 可用词 |

之后，项目里所有板都写这三项，不改写成「水灵大眼／琥珀瞳孔／樱桃小嘴」。

## 四、质量词三档政策

现有规则禁止「无验证作用的质量词堆砌」，但定妆级提示词确实需要一句渲染校准。按三档处理：

| 档 | 例子 | 处理 |
|---|---|---|
| A 可验证细节 | 漆皮反光／针织罗纹清晰／银链有细扣环／发丝根根可辨 | 鼓励，写在对应层 |
| B 渲染校准句 | 超高清8K细节／电影级角色渲染／PBR 物理渲染／SSS 次表面散射／85mm f/1.8 浅景深 | 受限可用：集中成**尾部一句**，每图最多一次，且必须在 A 档细节之后 |
| C 空泛套话 | 杰作／大师作品／best quality／完美／极致／顶级／无瑕疵／令人惊叹／惊艳 | 不写 |

B 档的用法：

- 只在项目确认走 3D/摄影管线时写；纯 2D 平涂项目写了会与线稿风格打架，删掉；
- 一句写完，不拆成多处，不与 C 档混写；
- 不得用来代替 L3~L9 的具体事实。删掉 B 档句子后，正文仍应能认出同一个人，否则细节不够；
- 相机参数只作「焦段感」提示，不承诺模型精确模拟光学（见 `common-recipe.md` 光学与表面描述）。

## 五、禁止项按失败模式分组

禁止项不是越长越好。定妆级样本常见的 30 条清单会稀释正面信息。做法：**先写正面要求，
负面只兜底**；按失败模式分 5 组，每组 2~4 条，只留本项目真出现过的。

| 组 | 典型条目 |
|---|---|
| 身份漂移 | 换脸／换发型／换配色／四视图不一致／多出第二个人物／丢失指定配饰 |
| 解剖错误 | 大头短腿／手指错误／肢体畸形／腿部弯曲／双脚缺失或裁切 |
| 材质错误 | 塑料皮肤／发丝粘连／服装穿模／纽扣错位／金属反光错误／面料廉价 |
| 风格越界 | 2D平面感（写实板）／真人粗犷骨相（3D板）／欧美脸／低模建模 |
| 版式与文字 | 视图重叠／头部或鞋底裁切／文字／水印／品牌Logo／边框／杂乱背景物 |

写作顺序建议：「必须完整展示 X、Y、Z」放在禁止项之前，用正面指令解决裁切，负面只补
「不得裁切」一句。**正面指令负责让模型做对，负面清单负责兜住已知的错**。

## 六、场景、道具、生物的分层

同一套逻辑，换层名：

| 类型 | 分层 |
|---|---|
| 地点 | 用途与观察方向 → 空间骨架（内/外、入口、主区、视觉轴）→ 固定锚点两两关系 → 材料与主次色 → 光与天气 → 陈设 state → 空场政策 → 排除 |
| 道具 | 用途与归属 → 轮廓与主要比例 → 尺度参照 → 材料与工艺 → 功能结构（铰链/开口/握持面）→ 当前状态 → 视图与背景 → 文字政策 → 排除 |
| 生物 | 用途 → 形体比例 → 头部与五官形制 → 毛发/鳞羽/斑纹 → 四肢与尾 → 配色 → 静止站姿 → 视图与背景 → 排除 |

道具的密度陷阱是「形容词代替结构」：写「精致古朴的木盒」不如写「掌心大小的浅棕胡桃木扁盒，
盖面铜质搭扣位于前缘正中，接缝可见细木纹」。生物的密度陷阱是「毛发只写质感不写走向」：
要写清斑纹的分布区与边界。

## 七、顺序即权重

生图模型对正文前段的服从度通常高于后段（按项目实测记录，不预设固定比例）。因此：

1. 版式与视图几何在前——排错了，后面画得再好也不可用；
2. 身份骨相与五官紧随其后——这是「同一个人」的判据；
3. 发型、配饰、服装按从头到脚的顺序，符合模型对身体的默认扫描顺序；
4. 体态与手部放在服装之后，避免过早的姿势描述干扰服装结构；
5. 光、背景；
6. 一致性句；
7. 渲染校准句（B 档）；
8. 禁止项。

## 八、失败征兆

- 通篇只有「精致、甜美、高级、氛围感」，删掉后画面不变；
- 服装写成「一套时尚造型」，没有逐件结构与材质；
- 同一层出现四个近义形容词（清纯／纯净／纯洁／清透），实际只表达一件事；
- 多视图里每块画面都重写一遍脸，四张脸互相打架；
- 禁止项比正面描述还长，且大量是「不要模糊、不要畸形」这类通用套话；
- 渲染校准句出现在开头，或同一张图出现三次；
- 细节写满但没人能说出这张图最该被认出的两三个锚点。

## 九、检查

| 检查 | 分类 |
|---|---|
| 每层是否只答一个问题、层次顺序是否稳定 | `craft_default` |
| 密度是否与用途匹配（定妆级板是否真的需要定妆级） | `craft_default` |
| 身份层是否在多视图里只写一次并配一致性句 | `reviewed_invariant` |
| 质量词是否落在 B 档且未替代事实 | `craft_default` |
| 禁止项是否按失败模式分组、是否否定必需项 | `reviewed_invariant` |
| 词表用法是否在同一项目内保持一致 | `craft_default` |
