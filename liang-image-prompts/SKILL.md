# 短剧资产图片提示词（本地定制）

把视觉事实写成可复用、可修改、可直接复制的角色板、场景板、道具板、生物板或状态图提示词，统一保存到 `剧集/<EP>/图片提示词.md`。每项用 `IMG-...` 标题，正文放在 `### 可复制提示词` 引用块。`IMG-...` 是提示词条目的稳定 ID；实际图片须由创作者提供，或来自经确认的生产结果。

每项使用 `## IMG-... · 中文名`，写一行不加粗的 `- 参考：`。无外部参考时写 `- 参考：无外部参考`；有真实图片时使用 `REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）`。多张用 `；` 连接，顺序从 1 连续编号；正文标题固定为 `### 可复制提示词`，每个非空正文行以 `>` 开头。`REF-...` 指向当前项目中的真实图片；下游分镜的 `PLAN-...` 挂图计划不能证明本条图片提示词已有参考输入。

## Quick Start

```text
用 $liang-image-prompts 为 EP001 已确定的人物、地点和道具写可直接复制的图片提示词
```

## 入口

有当前视觉设定即可直接开始；剧本只在提示词需要确认剧情状态时读取。Look Development 是可选分支。
先确认用途：身份板、造型/状态变体、地点板、道具板、生物板、组合 production sheet 或比较风格帧。
分镜需要生产尾帧时，可把已接受的「收尾关键帧提示词」落实为独立 `IMG-...` 状态图条目：说明来源
SHOT 与终点，沿用视觉事实和参考范围，不重新设计动作。实际生成以该 IMG 条目为来源。

创作者可读说明跟随项目语言；可复制正文跟随 `short-drama.json#/format/prompt_language`，配置了
`prompt_language` 时以它为准。未配置 `prompt_language`（含没有 `short-drama.json`）时，正文按确认表
「提示词规范」缺省值书写：**中英文结合，中文为主**，同一任务保持一致；不从创作者说明语言推断提示词
语言。项目配了 `prompt_language` 却与确认表「提示词规范」不一致时，先问创作者改哪一侧，不各写一套。

## 投产前确认

本技能只写提示词，不生成图片、不调用供应商。确认卡的作用是**锁定「图怎么出」的规格**
（平台、版式、风格、背景、提示词规范），规格确认后写正文。

**触发规则（只在真正要出图时弹卡，一次项目弹一次）：**

- 本次请求要**实际产出参考图**（在本套件投产、在你自己的工具出图、或由其他工具出图后
  绑回项目）时，且**项目里还没有已确认的资产图规格** → 弹确认卡。
- 项目里**已有已确认的资产图规格**（见「规格落盘」）→ 不重弹，直接沿用；创作者点名改规格时
  只弹改动项。
- 本次只写/改提示词文档、或为分镜冻结关键帧写正文（图片在分镜阶段另行产出）→ 不弹卡，
  直接写正文，规格沿用已确认项。

弹卡时先根据剧本内容识别涉及的资产类型，再按下列规则决定显示哪些确认表。

**强制规则（仅限触发确认卡时）：** 确认卡先于该批资产的可复制正文——未收到创作者对所选
规格的确认，不写这些资产的可复制正文。不弹卡的场景（纯文字改动、为分镜冻结关键帧写正文，
见上「触发规则」）不受此限：直接写正文并沿用已确认规格。

| 判定条件 | 显示 |
|---|---|
| 脚本里只出现人物 | 人物确认表 |
| 脚本里只出现道具 | 道具确认表 |
| 脚本里只出现生物 | 生物确认表 |
| 脚本里只出现场景 | 场景确认表 |
| 人物 / 道具 / 生物 / 场景 混合出现 | 只列被提及类型的确认表，未提及的补一句「未提及」 |
| 用户说「全部资产」或完全没指定类型 | 人物、道具、生物、场景四套确认表全部列出 |
| 用户明确排除某类 | 排除该类后列出其余 |

确认表锁定的是**规格**（平台、版式、风格、背景、提示词规范）；规格确认后，具体每张图的身份锚点、
造型差异、地理与尺度仍按 [通用配方](references/common-recipe.md) 与对应板子参考逐项写。下面四套表原样
保留，是本地产线的默认规格，可被创作者逐条改写。

**确认后执行：**

1. 读取视觉设定获取资产身份锚点；
2. 按对应规格编写提示词；
3. 写入 `剧集/<EP>/图片提示词.md`。

**规格落盘（确认之后必做）：** 创作者对规格表做了确认/改写后，把最终选定的
「生图平台、画面比例与视图/版式、画面风格、细节密度、背景色、提示词规范、场景内/外景」写进项目配置
（有 `short-drama.json` 时写进该文件的资产图规格段；没有时随项目根目录的既有配置）。后续
资产、状态变体、组合板请求**直接读已落盘规格，不再弹卡**；改规格须创作者点名并重新确认改动项。
落盘让规格成为「文件事实」：跨会话、跨集、换 agent 都不丢，也避免每写一批资产就重问一遍。

**没有已落盘规格、且本次不实际出图时**：正文按默认规格写，并在条目下加一行
`- 规格：待确认（默认：<所用规格>；出图前需创作者确认）`，把未决项留在文档里而不是口头带过。

**规格与既有字段的对应**（供创作者改写确认表时参照）：

| 确认项 | 落到的字段 / 参考 |
|---|---|
| 生图平台 | 决定正文词表取向（写实 CG 偏摄影质感，二次元偏线稿平涂），不影响 `IMG-...` 结构 |
| 细节密度 | 决定正文写几层、每层几个细节，以及渲染校准句是否保留，见 [细节密度](references/detail-density.md) |
| 画面比例与视图 | 即 `composition.view` / `framing`，进 [通用配方](references/common-recipe.md) 第 4 段 |
| 画面风格 | 对应项目制作形态，进 [形态投影](references/character-and-look.md#6-制作形态投影与模板槽位) 的词汇层 |
| 背景色 | 对应 [地点板](references/location-plate.md) / [道具板](references/prop-plate.md) 的背景与空场政策 |
| 提示词规范 | 对应 `#/format/prompt_language`，正文逐句按此语言书写 |

## 工作流

1. 锁定这一张图要固定的身份、状态、空间或比较变量。
2. 只读所需资产事实、视觉方向、负面约束和已提供参考图。
3. 按「主体与身份锚点 → 当前变体 → 构图/视角 → 光色/材质 → 背景边界 → 禁止项」写正文；
   需要逐件写到材质与五金时，按 [细节密度](references/detail-density.md) 的层序展开，
   身份层在多视图里只写一遍。
4. 每张参考只控制已声明的范围，并在 `REF-...` 槽位里写出封闭词表中的 `用途`；具体范围见
   [通用配方](references/common-recipe.md)。
5. 检查身份与变体、文字政策、视角和光线是否冲突。
6. 用户要全部资产就完成全部，资产组只是内部批次。

## 提示词要求

- 开头先写对象和用途，不用风格词淹没身份。
- 只包含当前图能同时满足的要求；多视图/状态对照写清版面关系。
- 保留稳定识别锚点，变体只改允许变化的部分。
- 被《视觉设定.md》连续性锁点名的条目，锁面原样出现在可复制正文里，让这张参考图本身就把跨镜事实定住。
- 按用途选细节密度：骨架级／标准级／定妆级，不默认写满（见 [细节密度](references/detail-density.md)）。
- 质量词分三档：可验证细节鼓励，渲染校准句限尾部一句，空泛套话不写。
- 可见文字、logo、水印、界面和字幕明确允许或禁止。
- 正文可直接复制，不含占位符、流程说明、文件路径或 QA 结论。

## 完成与投产

每个点名对象都有明确用途、可复制正文、参考边界和禁止项，且相互不矛盾，即完成。本次请求同时
修改图片提示词与分镜时，当轮刷新受影响镜头的「图片提示词项」，不另建对账产物。

**出图双路（本技能两条路都不写）：** 实际生成要么转官方套件的 `$short-drama-produce`
（展示精确任务并取得显式确认后执行），要么创作者用自己的工具出图后以 `REF-...` 绑回项目——
绑回的图片必须是项目内真实文件。本技能不调用外部服务、不写供应商参数。

五份创作文档齐备后，可转 `$short-drama` 对跨文档结构做一次机械核对；内容质量仍由创作者审查。

## 安装维护

只有安装、升级或排障时运行 `python scripts/selftest.py`（Windows 用 `python`，`python3` 常是
Microsoft Store 占位别名）。日常出提示词不跑任何脚本。
