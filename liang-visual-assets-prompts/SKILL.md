# 短剧视觉资产与图片提示词

从剧本提取可复用、可持续的视觉事实，统一写入 `剧集/<EP>/视觉设定.md`；
按创作者确认的平台规格，为每项资产写出可直接复制的图片提示词，落在 `剧集/<EP>/图片提示词.md`。

一份文件管一件事：本技能只拥有这两个文件。剧本语义归写作，镜头走位与分镜归分镜技能，
H3 视频提示词不归这里，音频与配音不归这里。下游只抄不改。
历史项目已存在《资产生图提示词.md》时沿用它继续写，不另建第二份；`check_assets.py` 对两个名字都认。

每项提示词用 `## IMG-... · 中文名` 标题，写一行不加粗的 `- 参考：`；无外部参考时写
`- 参考：无外部参考`。`IMG-...` 是提示词条目的稳定 ID，不表示真实图片；实际图片须由创作者
提供，或来自经确认的生产结果。下游分镜的 `PLAN-...` 挂图计划不能证明本条图片提示词已有参考输入。

## Quick Start

```text
用 $liang-visual-assets-prompts 从 EP001 剧本拆完人物、造型、生物、地点、道具，
并给每项写可复制的图片提示词
```

有当前视觉设定即可直接写提示词；剧本只在提示词需要确认剧情状态时读取。
Look Development 与局部修改是可选分支。分镜需要生产尾帧时，可把已接受的「收尾关键帧提示词」
落实为独立 `IMG-...` 状态图条目：说明来源 SHOT 与终点，沿用视觉事实和参考范围，
不重新设计动作；实际生成以该 IMG 条目为来源。

## 责任边界

| 事实 | 归谁 | 在本技能里的位置 |
|---|---|---|
| 身份（换一个就不再是同一个） | 本技能 | `视觉设定.md` 条目 |
| 变体（身份不变，服装/伤势/时段/开合改变） | 本技能 | 条目下的 `本集状态` / 变体条目 |
| 镜头瞬态（姿势、视线、左右手、站位、相机角度） | 分镜 | 不写，只在提示词里服从当前视图规格 |
| 故事语义（知识、目标、关系、情绪） | 写作 | 只引用可见后果，不推断 |

本技能**不生成图片**：实际出图要么走项目内生产 adapter（展示精确任务并取得显式确认后执行），
要么创作者用自己的平台出图后以 `REF-...` 绑回项目——绑回的图片必须是项目内真实文件。
本技能不调用外部服务、不写供应商参数。
`REF-...` 只指向项目里当前可读的真实图片，不得把对话里的描述、还没出的图、或
外部任务字段写成 `REF-...`。

创作者可读说明跟随项目语言；可复制正文跟随 `short-drama.json#/format/prompt_language`，
配置了 `prompt_language` 时以它为准。未配置 `prompt_language`（含没有 `short-drama.json`）时，
正文按确认表「提示词规范」缺省值书写：**中英文结合，中文为主**，同一任务保持一致；
不从创作者说明语言推断提示词语言。项目配了 `prompt_language` 却与确认表「提示词规范」
不一致时，先问创作者改哪一侧，不各写一套。

## 硬门禁：投产前确认卡

本技能调用后**先拆资产再弹卡**：读现有事实（剧本、《视觉设定.md》、已有参考图、项目视觉方向），
输出《资产生图参数确认卡》；确认前不写最终文件、"继续"不算确认。

**弹卡触发规则（只在真正要出图时弹，一次项目弹一次）：**

- 本次请求要**实际产出参考图**（在本套件投产、在创作者自己的工具出图、或由其他工具出图后
  绑回项目），且**项目里还没有已确认的资产图规格** → 弹确认卡。
- 项目里**已有已确认的资产图规格**（见「规格落盘」）→ 不重弹，直接沿用；创作者点名改规格时
  只弹改动项。
- 本次只拆资产写视觉设定、只写/改提示词文档、或为分镜冻结关键帧写正文（图片在分镜阶段
  另行产出）→ 不弹卡，直接写正文，规格沿用已确认项。
- 强制规则（仅限触发确认卡时）：确认卡先于该批资产的 IMG 可复制正文——未收到创作者对所选
  规格的确认，不写这些资产的可复制正文。

根据剧本识别涉及的资产类型，按以下规则决定显示哪些确认表：

- 剧本里只出现人物 → 只显示人物确认表；
- 只出现道具 → 只显示道具确认表；
- 混合类型 → 只显示被提及类型的确认表（未提及的补为"未提及"）；
- 用户说"全部资产"或完全没指定类型 → 人物、生物、场景、道具四套全列；
- 用户明确排除某类 → 排除后列其余。

确认卡至少包含：

```markdown
## 资产生图参数确认卡
- 项目 / 剧集 / 场次范围：
- 识别出的资产类型与数量：
- 拟新建 / 复用 / 变体 / 未决：
- 生图平台：gpt / 香蕉 / z-image_tubo / 千问2.1-image / 即梦 / moss / h3生图
- 画面比例与视图（按类型，见确认表）：
- 画面风格：2D二次元 / 3D国风 / 写实CG / 赛博朋克
- 细节密度：骨架级 / 标准级（默认）/ 定妆级（见 references/detail-density.md；决定每个条目写几层锚点）
- 背景色（场景类用原生环境或绿幕）：
- 提示词语言：随项目（当前解析为 ××）/ 或指定
- 提示词存放位置：剧集/<EP>/图片提示词.md（历史项目已存在《资产生图提示词.md》时沿用它）
- 连续性与跨镜锁需求（见"连续性锁"节）：
- 待创作者决定：只列真正影响成稿的选择
```

**规格落盘（确认之后必做）：** 创作者对规格表做了确认/改写后，把最终选定的
「生图平台、画面比例与视图/版式、画面风格、细节密度、背景色、提示词语言、场景内/外景」写进项目配置
（有 `short-drama.json` 时写进该文件的资产图规格段；没有时随项目根目录的既有配置）。后续
资产、状态变体、组合板请求**直接读已落盘规格，不再弹卡**；改规格须创作者点名并重新确认改动项。
落盘让规格成为「文件事实」：跨会话、跨集、换 agent 都不丢，也避免每写一批资产就重问一遍。

**没有已落盘规格、且本次不实际出图时**：正文按默认规格写，并在条目下加一行
`- 规格：待确认（默认：<所用规格>；出图前需创作者确认）`，把未决项留在文档里而不是口头带过。

**规格与既有字段的对应**（供创作者改写确认表时参照）：

| 确认项 | 落到的字段 / 参考 |
|---|---|
| 生图平台 | 决定正文词表取向（写实 CG 偏摄影质感，二次元偏线稿平涂），不影响 `IMG-...` 结构 |
| 细节密度 | 决定正文写几层、每层几个细节，以及渲染校准句是否保留，见 [细节密度](references/detail-density.md) |
| 画面比例与视图 | 即 `composition.view` / `framing`，进 [提示词配方](references/prompt-recipe.md) 第 4 段 |
| 画面风格 | 对应项目制作形态，进 [形态投影](references/character-and-look.md#制作形态与身份锚点的可表达性) 的词汇层 |
| 背景色 | 对应 [地点与视图](references/location-and-view.md) / [道具与状态](references/prop-and-state.md) 的背景与空场政策 |
| 提示词规范 | 对应 `#/format/prompt_language`，正文逐句按此语言书写 |

## 工作流

1. **读范围与视觉方向**。读当前集剧本、已有《视觉设定.md》、项目视觉方向与制作形态。
   视觉方向未定且会实质影响识别通道时（写实锁脸 vs 剪影认人），向创作者给出选择，
   不从对话记忆补造。
2. **解析提示词语言**。项目根有 `short-drama.json` 时读 `format.prompt_language`；
   没有就默认中文。这是可复制正文的书写语言，也是连续性锁面必须能匹配的语言。
   `video_prompt_language` 属于视频阶段，本技能不读、不写。
3. **逐场做出项提取**。对每个场景段扫一遍，把每个可能相关的实体按四种出项方式标注：
   **明示出镜** / **仅被提及** / **关键操作物** / **背景布景**。只把需要识别、复用、
   承接连续性或后续要绑定参考图的，升级为资产；仅被提及而不出镜的实体不建板。
   写法见 [文档与出项提取](references/documents-and-extraction.md)。
4. **定身份与版本**。对每个出项决定 `reuse / new_variant / new_asset / unresolved`；
   含混指代、匿名人、"另一把钥匙"不猜。证据不足标 `unresolved` 并列出会改变的下游影响。
   判断细则见 [身份与变体](references/identity-vs-variant.md)。
5. **写最小可识别设定**：`识别锚点`（可见、可生成、可比较，不用空泛质量词）＋
   本集状态与变化原因＋有效范围。人物/造型、地点/视图、道具/状态的写法分别见
   [人物与造型](references/character-and-look.md)、[地点与视图](references/location-and-view.md)、
   [道具与状态](references/prop-and-state.md)。
6. **补时代锚点**。从项目视觉方向取下时代锚点，在地点、造型、道具条目写出可执行的
   时代形制（材质、工艺、标识、器物代际）。"旧/老式/复古"一类词必须有原著依据或
   创作者选择，不由常识补齐。
7. **查连续性变化**。检查造型/伤势、持物与所有权、道具开合与内容物、地点时段/天气/光态，
   以及跨场跨集的结束状态；变化写成带前态、后态、原因、生效范围和受影响条目的记录。
8. **上连续性锁**。给跨镜出现且观众看得出不一致的可见事实写锁，锁写在它所属条目下，
   镜头范围先写 `入画`。语法与判据见 [连续性锁](references/continuity-lock.md)。
9. **写画面代称**。提示词语言不是中文时，给每个人物条目写一行 `画面代称：<正文里的拼写>`；
   正文从不点名它就写 `画面代称：无`。
10. **输出确认卡并停止**（触发规则见上节）。创作者确认后：
    - 按确认规格在 `剧集/<EP>/图片提示词.md` 逐项写 `IMG-...` 条目与可复制正文；
      先指向《视觉设定.md》准确条目与当前变体，再按
      [提示词配方](references/prompt-recipe.md) 的八段式写正文；
    - 有真实参考图时用 `REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：…；控制：…；不得控制：…）`；
      缺参考图的写 `- 参考：无外部参考`，不伪造路径；
    - 状态变体板、Lookdev 风格帧、局部修改 edit-delta、组合板分别见
      [变体板](references/look-and-state-variant.md)、[Lookdev 帧](references/lookdev-frame.md)、
      [定点修改](references/edit-and-revision.md)、[Production Sheet](references/production-sheet-recipes.md)；
    - 全部条目写完后统一人工过一遍（不跑脚本、不逐条跑）：锁面逐字在正文里、
      文字政策与呈现方法不冲突、无占位符。
11. **补下游缺口**。整集请求一次处理完整集，末端一次回报：关键身份决定、未决指代、
    参考图缺口、锁的生效范围，以及需要下游同步的文件。
12. **跑自检（一次）**。`python scripts/check_assets.py 剧集/<EP>`：按报错改一轮，
    重跑一次确认；仍不过的写进报告逐条说明为什么保留，不再迭代。

## 运行纪律（防拖慢）

- 全流程只有三次停点：读事实 → 弹确认卡停 → 成稿 → 跑一次 `check_assets.py` → 交付。
  不要为每个 `IMG-...` 条目单独跑脚本，也不要边写边跑。
- 不要为验证检查器另造反例文件（`_neg*.md`、`_test_*.md`、`tmp_*.py`），
  也不要改 `scripts/check_assets.py` 去迁就成稿。检查器是尺子，不是交付物。
- 用系统已装的 `python`（Windows 用 `python`，不要用 `python3`——常是 Microsoft Store 占位别名），
  不要去找 ComfyUI 或其他软件自带的 python。
- 交付前把临时脚本和测试稿删干净。

## 连续性锁（给下游分镜/视频提示词留抓手）

三条同时成立才值得上锁：

1. 该可见事实本集出现于两个以上镜头，或一个镜头加一张资产板；
2. 观众能直接看出前后不一致；
3. 它不随剧情改变——会变的是状态，**状态不上锁**。

典型：服装主色与形制、道具主色与材质、发型长度、伤口位置与形状、招牌或界面的形制配色。
不典型：情绪、姿势、镜头角度、时段光线、破损进度、持有人——归状态或分镜。

锁面是**要逐字带进下游提示词正文的最小可辨识词组**（颜色＋材质/形制＋物体），
例如 `pine-green lapel service jacket`。语法：

```markdown
## 造型 · 江晨常服
- 识别锚点：……
- 连续性锁：LOCK-JIANGCHEN-DRESS《江晨松枝绿常服》（镜头：入画；生图提示词项：IMG-LOOK-JIANGCHEN-DRESS）· 锁面：pine-green lapel service jacket
```

- 锁面必须逐字出现在《图片提示词.md》对应条目的可复制正文里，让参考图本身
  就把跨镜事实定住；下游 H3 分镜与视频提示词再原样抄走；
- 一集里的锁通常是个位数；把每条识别锚点都升级成锁，会挤掉提示词真正要执行的内容；
- 比较忽略大小写与换行，其余逐字；锁面前后可接语法，内部不能改写；
- 服装锁写在 `造型` 条目下而不是 `人物` 条目下——人物条目会被手部、眼部特写引用，
  写在那里会强迫所有特写都写进看不见的衣服。

细则、反例与校验规则见 [连续性锁](references/continuity-lock.md)。

## 图片提示词要求

每项使用 `## IMG-... · 中文名` 标题；正文标题固定为 `### 可复制提示词`，每个非空正文行以 `>` 开头，
整段粘出去就能用。开头先写对象和用途，不用风格词淹没身份；只包含当前图能同时满足的要求，
多视图/状态对照写清版面关系；保留稳定识别锚点，变体只改允许变化的部分。

按八段式顺序组织正文，省略不适用段，不省略类型必需事实：

1. 用途与主体（这是人物设定图／场景空镜／道具参考／哪套视图，主体是谁）
2. 稳定锚点（身份、地理或形制的持久事实）
3. 版本差异（这次相对基准版本变了什么）
4. 构图与尺度（视角、画幅用途、主体占比、方向、相对位置、比例参照）
5. 材质、色彩与光线（对识别有用的表面、主次色关系、光向与亮暗逻辑）
6. 背景/舞台政策（干净背景、环境内展示、空场）
7. 文字与功能（先引资产来源政策，再明确 `readable / symbolic / blank / postproduction`）
8. 排除与保留（只写当前最可能出现的误读；局部修改先写必须保留什么）

硬性要求：

- 视角与视图规格来自确认卡，提示词正文与确认结果一致；
- 人物/生物/道具同一对象跨视图的身份、配色、站姿统一，正文写死"完全统一"；
- 被《视觉设定.md》连续性锁点名的条目（`IMG-13`），锁面原样出现在可复制正文里；
- 可见文字按两层政策写：资产来源政策 `exact_readable / graphic_only / no_readable_text /
  pending_creator_text` 决定真相，呈现方法 `readable / symbolic / blank / postproduction`
  决定这张图怎么处理，映射表见 [提示词配方](references/prompt-recipe.md)；不得同时要求
  `readable` 和全局"不要文字"；
- 每张真实参考图只承担一个用途，用途取封闭词表
  `身份 / 造型状态 / 地理 / 构图 / 尺度 / 效果 / 起始帧 / 结束帧 / 风格`（资产板不用 `起始帧`、`结束帧`），
  一张图承担两件事就拆成两个槽位，不写"全参考"；
- 人物条目要量化脸型骨相与识别特征（脸型角度、疤痕尺寸、不对称对位），识别特征成对出现，
  作为下游跨镜锁脸的抓手；写法见 [人物与造型](references/character-and-look.md)；
- 细节密度按用途三选一（骨架/标准/定妆），定妆级按层写全，词表与层序见
  [细节密度](references/detail-density.md)；多视图里身份层只写一遍；
- 质量词分三档：可验证细节鼓励，渲染校准句限尾部一句，空泛套话不写；避免无验证作用的
  堆砌（`ultra detailed`、`8k`、`杰作`）；定妆级确需一句渲染校准时，
  只放尾部一次，且必须在具体材质细节之后（见 [细节密度](references/detail-density.md#六质量词三档)）；
- 不写引擎专用语法（`--ar 9:16`、`(red coat:1.2)`、`cat::2`），那是平台适配器的职责；
- 正文可直接复制：不含占位符、ID 之外的内部字段、文件路径、流程说明、审查结论，
  也不含"请模型务必""根据上图保持一致"之类的对话残留。

## 自检

```bash
python scripts/check_assets.py 剧集/<EP>
python scripts/check_assets.py 剧集/<EP> --partial   # 只有视觉设定时
python scripts/selftest.py                           # 只在安装/升级/排障时跑
```

检查器**只跑一次**，按报错改一轮后重跑确认即可；不要为验证检查器另造反例文件，
也不要改 `scripts/check_assets.py` 去迁就成稿。检查器只机械核对：条目与 ID 结构、
参考槽位语法与用途词表、锁语法与锁面是否真的出现在被点名的正文里、占位符与引擎语法残留、
文字政策与呈现方法的显式冲突。
该不该上这把锁、锚点写得准不准、资产拆得对不对，仍由创作者与审查判断；检查器通过不等于
资产正确。规则 ID 与错误码对照见 [规则与错误码](references/rule-index.md)。

## 完成

- 每个出项都已 `reuse / new_variant / new_asset / unresolved` 之一，未决项写明下游影响；
- 需要保持的视觉事实、时代形制与连续性变化已写入《视觉设定.md》；
- 确认后《图片提示词.md》逐项有规格一致的可复制正文，连续性锁锁面原样入正文；
- 每个点名对象都有明确用途、参考边界和禁止项，且相互不矛盾；
- 参考图缺口、未决指代、被阻断的条目在末尾逐项说明；
- 自检通过，或每条未通过项都有说明；
- 生图提示词写完即停。实际出图走创作者自己的平台或项目内生产 adapter；
  分镜、H3 视频提示词、音频不归本技能。

写完本阶段文档后，按需转下游技能：分镜走 `$liang-h3-storyboard-prompts`。是否开始由用户点名，
本技能不自动串联。五份创作文档（剧本、视觉设定、图片提示词、分镜、视频提示词）齐备后，
可转官方套件 `$short-drama` 对跨文档结构做一次机械核对；内容质量仍由创作者审查。

## 安装维护

脚本需要 Python 3.9 或更高版本，其余功能不依赖 Python。排障或升级时在本技能目录下运行
`python scripts/selftest.py`（只在这两种场合跑）。本机若没有可用的解释器（Windows 上
`python`/`python3` 可能只是 Microsoft Store 的占位别名），先 `python --version` 确认能打印出
版本号再执行；没有解释器时跳过全部脚本，按人工核对交付，不要为跑脚本而临时安装环境。
