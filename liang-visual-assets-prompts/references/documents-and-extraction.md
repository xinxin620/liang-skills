## 本技能拥有的两份文件

| 文件 | 管什么 | 不管什么 |
|---|---|---|
| `剧集/<EP>/视觉设定.md` | 身份、变体、识别锚点、本集状态、连续性锁 | 镜头走位、构图、提示词文案 |
| `剧集/<EP>/资产生图提示词.md` | 每项资产的 `IMG-...` 条目与可复制正文、参考槽位 | 资产事实本身、出图执行、任务参数 |

只写这两份。项目里已有《图片提示词.md》时把 `IMG-...` 并入它，不建第二份权威；
已有《分镜.md》《视频提示词.md》时只读不写——它们是下游，锁的生效范围在那里落地。

## 视觉设定.md 骨架

```markdown
# EP001 视觉设定

## 项目视觉方向
- 时代锚点：当下（2020 年代）；设备：全面屏智能手机、笔记本电脑；制服：现行常服；
  陈设：白色工位桌、网面办公椅；光：嵌入式 LED 面板灯，冷白。
- 制作形态：2D二次元
- 识别通道：面部五官锁脸（写实）／轮廓与配色认人（风格化）
- 提示词语言：zh

## 人物与造型

### CHAR-JIANGCHEN · 江晨
- 身份锚点：方额窄下颌；右眉尾一道约一厘米旧疤；左耳垂有一枚小孔。
- 尺度次序：江晨最高；魏叔比江晨矮约一头。
- 画面代称：Jiang Chen

#### LOOK-JIANGCHEN-DRESS · 江晨常服
- 变体锚点：松枝绿翻领制服外套＋同色直筒长裤，铜扣单排五粒。
- 本集状态：SC002 起右袖肘部有磨损；其余不变。
- 连续性锁：LOCK-JIANGCHEN-DRESS《江晨松枝绿常服》（镜头：入画；生图提示词项：IMG-LOOK-JIANGCHEN-DRESS）· 锁面：pine-green lapel service jacket
- 来源：SC002、SC005

## 生物

## 地点与视图

### LOC-OLDSTATION-DUTY · 旧渡站值班室
- 地理锚点：单间，北墙为唯一外门；东墙一排高窗；西南角配电箱。
- 尺度参照：房高约两步半；门洞高过江晨半个头。
- 视图：VIEW-DUTY-NORTH / VIEW-DUTY-EAST（各绑参考图）

## 道具与状态

### PROP-TIN-CASE · 铁皮匣
- 形制锚点：手掌至小臂长度的扁长黑铁匣，铰链盖，右前角永久凹陷。
- 文字政策：`exact_readable`（匣盖内侧"潮位 7"）
- 状态：PSTATE-TIN-CLOSED-BADGE-IN（闭合，白瓷号牌在内，柜台下层）

## 跨场连续性
- SC004 → SC006：号牌由铁皮匣转到江晨右手，未归还。
- EP001 结束状态：铁皮匣空且打开；值班室断电；江晨右袖肘磨损。
```

条目 ID 前缀：人物 `CHAR-`、造型 `LOOK-`、地点 `LOC-`、视图 `VIEW-`、道具 `PROP-`、
道具状态 `PSTATE-`、生物 `CREA-`、锁 `LOCK-`。ID 与中文名并列，中文名给创作者读，
ID 给下游引用；两者都不藏在二级文件里。

## 资产生图提示词.md 骨架

```markdown
# EP001 资产生图提示词

- 生图平台：即梦
- 画面风格：2D二次元
- 提示词语言：zh（中英混写，中文为主）
- 已确认规格：人物 16:9 三视图 ／ 场景 B 机位组合板 ／ 道具 16:9 三视图

## IMG-LOOK-JIANGCHEN-DRESS · 江晨常服三视图

- 资产：`视觉设定.md` · 人物与造型 · 江晨 / LOOK-JIANGCHEN-DRESS
- 用途：`character_sheet`
- 视图：16:9 三视图（左侧半身特写占 50% 宽度并占满高度，右侧正面全身＋背面全身均分剩余宽度）
- 文字政策：`no_readable_text` → `blank`
- 参考：`REF-front（顺序：1）· 输入/江晨_正面.png《江晨正面定妆照》（用途：身份；控制：面部骨相与发型；不得控制：服装与姿势）`

### 可复制提示词

> 人物设定三视图，主体是江晨，松枝绿翻领制服外套……
```

规则：

- 一条目一资产（或一个造型/一个视图），标题为 `## IMG-<后缀> · <中文名>`；
- `资产：` 必须指到《视觉设定.md》的准确条目与当前变体，不按名字相似猜；
- `文字政策：` 同时写两层，`来源政策 → 呈现方法`，中间用箭头；
- 没有真实参考图就写 `- 参考：无外部参考`，不留空行、不编路径；
- `### 可复制提示词` 下每一行都以 `>` 开头，整段粘出去就能用；
- 正文内的 ID、来源、审查结论一律不写；元信息只在上面的字段里。

## 交接：ID 与引用

- 跨文档引用视觉事实用条目中文标题；引用提示词条目才用 `IMG-...`；
- `IMG-...` 只定位提示词条目，不代表一张真实图片；真实图片用 `REF-...` 槽位；
- `REF-...` 槽位语义一旦分配就固定：调顺序或插入新槽位不能改变已有槽位的含义；
  换图时在同一槽位明确修订路径，不把旧图的控制边界静默转给新槽位；
- `SHOT-...`、`MOTION-...` 属于下游，本技能只写进锁的受影响列表，不自行创建。

## 出项提取

先保存"某段剧本在哪处要求了什么"的证据，再判断它对应哪个资产。逐个与制作有关的剧本段
回答六个问题：

1. **谁或什么需要被看见、听见**？人物、群体、生物、地点或可操作道具。
2. **以什么方式出现**？`on_screen`（出镜）、`voice_only`（只有声音）、
   `represented`（照片/屏幕/画像中出现）、`mentioned_only`（只被提到）。
3. **此刻能直接看到什么**？只摘剧本已给出的外观、状态、位置和动作后果。
4. **制作时必须实现什么**？服装、伤污、可读文字、内容物、功能状态、关键入口。
5. **它为什么重要**？识别、行动、信息揭示、关系与权力、交接、气氛或普通布景。
6. **它从哪里来、要去哪里**？进入状态、同场变化和结束状态。

一个动作句常带出多个资产。例如：

> 江晨推开旧渡站值班室的北门，把带裂口的白瓷号牌放进铁皮匣。匣盖内侧写着"潮位 7"。

至少记录：江晨出镜；值班室出现，北门可能是固定空间锚点；号牌有裂口；铁皮匣被打开，
匣盖内出现必须保留的文字。**不要**把"北门""裂口""潮位"各建成资产。

提取过程在上下文里整理即可，结论写进 `视觉设定.md` 对应条目，不另建出现记录文件。

## 事实分层

| 内容 | 写在哪 | 写法 |
|---|---|---|
| 剧本段与场次位置 | 条目的 `来源：` | 场景 ID 加动作/对白标签或必要短引文，不复制整段正文 |
| 剧本明示的可见事实 | `识别锚点` / `本集状态` | 简短摘义，指回同一场景 |
| 资产判断 | 条目本身的有无 | 只留 `reuse / new_variant / new_asset / unresolved` 结论 |
| 连续性变化 | `跨场连续性` 与条目状态 | 指向同一身份的前后状态 |

不要把推测伪装成可见事实。"匣盖被推开"可以直接记为 `open`；"江晨很内疚"不能只因
她低头就升级成资产事实。

## 称谓、代词与匿名对象

- 原文写"她"但本段没有唯一先行人物：把决定标为 `unresolved`，列出候选与需确认项；
- "穿雨衣的人"后来被叫出姓名：可以提出合并，但必须展示前后剧本证据，
  不能只因服装相同就自动认定是同一人；
- "另一把钥匙"说明它不是上一把，但不知对应哪个已有 ID：建立独立出项并标 `unresolved`；
- 同一人由职务、关系和名字交替称呼：别名只有创作者接受后才能进入人物资产；
- 群体称谓先按制作用途处理，没有个体连续性的"候车乘客"作为群组或普通布景；
  后来接过关键道具的那个人单独建人物条目。

## 出项不等于视觉资产

- `voice_only` 需要人物或声音事实，但本场不一定需要造型绑定；
- `represented` 可能需要同一人物的历史造型，也可能只是不可辨认的照片，不默认露脸；
- `mentioned_only` 通常只保留故事追踪，不触发图片资产；若台词要求观众读到某份文件，
  还要建立道具条目；
- 环境中的普通桌椅标为 `set_dressing`；只有承担动作、识别或连续性时才升级为道具。

只有会改变识别、复用、提示词、镜头或连续性的事实才进入资产表。项目有特别制作原因
（品牌布景需逐件批准）时写明原因后调整。

## 时代锚点

拆资产之前，先依据原著与剧本中的事实判断时代：设备、平台与传播方式、流行语、写明的年份，
或能从年龄与事件推出的年代。在 `视觉设定.md` 顶部的项目视觉方向写一行时代锚点：
先写年份或年代，再写设备、制服、家具和灯光在这个年代长什么样。

原著没有能定时代的事实时，把时代标为"需创作者决定"，**不默认成过去**。

`旧 / 老式 / 复古 / 褪色 / 斑驳`，以及 old、worn、dusty、period、CRT 这类让画面变旧的词，
要有原著依据或创作者明确的选择；两样都没有就删掉，改用时代锚点里的写法。
原著写某件东西旧，旧是**这件物**的状态，写在它自己的条目里，不把整个地点带回过去。

地点、造型和道具条目在年代会改变外观的地方写具体形制：写液晶显示器，不写"显示器"；
写现行常服，不写"军装"。提示词照条目写，时代线索就随条目传给下游。

## 连续性变化记录

状态表回答某个边界"现在是什么状态"；变化记录回答"什么变了、变化前后分别是什么、
原因是什么、何时生效、影响谁"。不要在每场复制完整设定表。

每条变化写清五件事：前态、后态、原因/来源场景、有效范围（无明确终点写 `open_ended`）、
受影响的已存在条目（`IMG-...` / `SHOT-...` / `MOTION-...`）。"更新了"不能代替前后状态。

需要追踪的五组：

1. 人物的故事状态（知情、信念、目标、关系与情绪）——只在影响后续行动或审稿时追踪，
   指向写作的准确来源，**不在资产环节自行发明**；
2. 人物的可见状态（造型、伤势、污湿、场景级携带物），单镜姿势归分镜；
3. 地点状态（地点、观察视角、可用入口、时段、天气、光线、关键陈设）；
4. 道具状态（版本、负责人、持有人、位置、状况、内容物、可读文字）；
5. 场次/集间交接（上一场结束状态 → 下一场进入状态）。

两条容易错的：

- **"未知"不等于"恢复默认"**：上一集结尾仍带伤，本集没提伤势，不能自动恢复无伤；
  保留最后一次确认的状态，并把连续性问题标 `unresolved`。
- **知道事实不等于知道对方也知道**：身份与秘密要区分"甲知道""乙知道""甲知道乙已知道"。

有剧本来源不等于变化合理。引用某段只能证明变化有文字来源，不能自动证明因果成立——
"灯闪了一下"不足以解释整栋楼永久断电。

## 交接检查

- 每个相连场次的结束状态与下一场进入状态一致，或已有明确修订；
- 转手说明从谁手中到谁手中，物件不会在两人手里复制；
- 伤势、造型、天气、光线不会无原因复位；
- 道具内容状态与人物知情情况分开记录；
- 变化的有效范围覆盖所有依赖镜头，且不会提前生效；
- 受影响列表覆盖已存在的提示词条目，修订时重新计算实际使用方；
- 结束状态足以让下一集继续，不依赖创作者脑内记忆。
