# 细节密度：识别锚点写到什么颗粒度

`prompt-recipe.md` 管八段式的顺序，本文件管**第 2、3、5 段写多细**：识别锚点、本集状态、
材质与色彩各写几层、每层只答什么问题、可用哪些词。它不改 `AST-04`（锚点与状态不混写），
而是把「可见、可生成、可比较」展开成可执行的层与词。密度是 `craft_default`。

## 一、三级密度

密度按**每层有几个可比较细节**衡量，不按字数。

| 级别 | 用在哪 | 每层细节 | 视觉设定里的写法 |
|---|---|---|---|
| 骨架级 | 群演、远景识别、单场次背景人物 | 0~1 个，只留区分性锚点 | 一行锚点，如「窄长脸；黑短卷发；肩背略前倾」 |
| 标准级 | 默认人物/造型/地点/道具条目 | 1~2 个 | 分号分隔的 3~6 项锚点，每项带可见依据 |
| 定妆级 | 主角、跨集复用、需要跨镜锁脸锁装 | 3~6 个，逐件到材质与五金 | 锚点分骨相/五官/发型/配饰/服装/体态六行，另配连续性锁 |

判定：**只有下游真的要靠这条参考图认人时才上定妆级**。写满了却不服务识别，等于给下游
增加漂移面，也让锁变得不可读。

## 二、人物条目分层

`视觉设定.md` 的人物/造型条目按下列层写锚点。顺序固定，因为下游提示词照抄时也按这个顺序走。

| 层 | 只回答一个问题 | 写进哪 |
|---|---|---|
| L1 骨相 | 凭什么从轮廓认出这张脸 | Character `识别锚点`（脸型、额头、面中/颧骨、下颌线、下巴、比例） |
| L2 五官 | 眼鼻唇眉各是什么形 | Character `识别锚点`（眼型与眼尾、眼皮、睫毛、瞳色、眼妆、眉形、鼻梁鼻尖、唇形唇色） |
| L3 皮肤 | 表面质感与冷暖 | Character `识别锚点`（冷暖＋深浅＋是否保留纹理；不写「完美肌肤」） |
| L4 发 | 头发怎么长、怎么梳 | 稳定部分（发质、发色、发际）进 Character；梳法、分缝、刘海、长度变化进 Look |
| L5 配饰 | 戴什么、在哪、什么材质 | 不随 Look 变化的进 Character；随造型换的进 Look |
| L6 服装 | 从上到下逐件 | Look `变体锚点`，逐件写版型、领口、袖口、材质、五金、颜色、穿法 |
| L7 体态 | 比例与重心 | Character `识别锚点`（肩背、重心、步态；身高次序写在 `尺度次序`） |

**`reviewed_invariant`**：L4 的「发型长度」既是识别事实又会随造型变。写清哪部分跨造型不变
（发际形状、发质、能否扎起），哪部分属 Look（今天的分缝与长度），否则同一人换个发型就被
判成另一身份。

## 三、受控词表

同一项目内**同一角色、同一件衣服、同一种光反复用同一组词**。一致性靠复述同一词组建立，
不靠换近义写法。

| 维度 | 可用词 |
|---|---|
| 脸型 | 鹅蛋脸／瓜子脸／圆脸／方脸／窄长脸／菱形脸 |
| 骨相 | 额头饱满／面中立体／颧骨内收／下颌线纤细／下巴短小圆润微尖 |
| 眼 | 杏眼／桃花眼／圆眼／凤眼／狭长眼；窄双眼皮／内双；眼尾微扬／自然延长 |
| 瞳 | 深棕通透／灰棕偏粉玻璃瞳／琥珀／灰蓝 |
| 眉 | 细眉／弯眉／平眉；眉尾自然收细／眉尾短缺口 |
| 鼻 | 鼻梁纤细窄直／高挺；鼻尖小巧／圆润 |
| 唇 | M形花瓣唇／薄唇／饱满唇；自然闭合／微启；低饱和豆沙粉／珊瑚粉 |
| 肤 | 冷调自然白／暖调瓷白／浅象牙粉；清透／保留真实纹理 |
| 发色 | 深棕近黑／黑茶／墨棕／银白／浅香槟银灰 |
| 发型 | 高颅顶／蓬松发根；中分／四六分／侧分；轻薄碎刘海／空气刘海；及肩／垂至胸口／至腰 |
| 服装 | 修身／宽松／落肩／收腰／A字／直筒／高腰；翻领／圆领／V领／吊带；棉质／雪纺／缎面／针织／漆皮／网纱 |
| 五金 | 银色细链／圆环扣／星形吊坠／四孔纽扣 |
| 鞋袜 | 中筒堆堆袜／厚底运动鞋／厚底乐福鞋／漆皮圆头皮鞋 |
| 光 | 柔和影棚布光／均匀平光／侧后方轮廓光／自然天光（写明主太阳方向） |

词表用来**选词**，不是每张板都填满。选定「杏眼＋灰棕玻璃瞳＋M形花瓣唇」后，项目里所有
正文都写这三项，不改成「水灵大眼／琥珀瞳孔／樱桃小嘴」。

## 四、质量词三档

| 档 | 例子 | 处理 |
|---|---|---|
| A 可验证细节 | 漆皮反光／针织罗纹清晰／银链有细扣环／发丝根根可辨 | 鼓励，写在对应层 |
| B 渲染校准句 | 超高清8K细节／PBR 物理渲染／SSS 次表面散射／85mm f/1.8 浅景深 | 受限可用：尾部一句，每图一次，且必须在 A 档之后 |
| C 空泛套话 | 杰作／大师作品／best quality／完美／极致／顶级／无瑕疵 | 不写 |

B 档只在该项目确认走 3D/摄影管线时写；纯 2D 平涂项目写了会与线稿风格打架。删掉 B 档句子后
正文仍应能认出同一个人，否则是细节不够，不是渲染词不够。

## 五、地点、道具、生物的分层

| 类型 | 分层 |
|---|---|
| 地点 | 空间骨架（内/外、入口、主区、视觉轴）→ 固定锚点两两关系 → 材料与主次色 → 光与天气 → 陈设 state → 空场政策 |
| 道具 | 轮廓与主要比例 → 尺度参照 → 材料与工艺 → 功能结构（铰链/开口/握持面）→ 当前状态 → 文字政策 |
| 生物 | 形体比例 → 头部与五官形制 → 毛发/鳞羽/斑纹（写分布区与边界）→ 四肢与尾 → 配色 |

道具的密度陷阱是形容词代替结构：「精致古朴的木盒」不如「掌心大小的浅棕胡桃木扁盒，盖面
铜质搭扣位于前缘正中，接缝可见细木纹」。生物的陷阱是只写质感不写走向：「毛发浓密」不如
「颈背一列深色鬃毛，斑纹从肩部向腰侧由密转疏」。

## 六、细节写多了会坏事的三种情况

1. **与身份冲突**：为了「精致」把已接受的方脸、厚重体格写成瓜子脸、九头身。模板默认值
   不得覆盖身份锚点（见 [人物与造型](character-and-look.md#模板槽位不得覆盖身份锚点)）。
2. **与状态冲突**：把临时伤势、雨水、当天妆容写进 Character 持久锚点。
3. **无法生成或无法比较**：写「眼中有星河流转」这类不可执行的比喻，或写下游看不清的
   微观差异（三根睫毛的间距）。锚点必须能被一张参考图证明。

## 七、检查

| 检查 | 分类 |
|---|---|
| 每层是否只答一个问题、层次顺序是否稳定 | `craft_default` |
| 密度是否与复用职责匹配（不是每人都定妆级） | `craft_default` |
| 临时状态是否误入持久锚点 | `reviewed_invariant` |
| 同一角色的词是否项目内保持一致 | `craft_default` |
| 质量词是否落在 B 档且未替代事实 | `craft_default` |
| 跨角色是否出现逐字重复、与身份无关的模板句 | `reviewed_invariant` |
