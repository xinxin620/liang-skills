## 输入

资产提示词把已接受资产中需要保持的事实，写成便于识别、比较和后续复用的参考图要求。

写正文前手上必须有：《视觉设定.md》中准确的条目和当前变体、来源场景、用途、
确认卡里已定的构图与视图规格、视觉风格、背景与光线、文字政策、真实参考图与缺口、
约束与排除项。身份未确定时停在提案，不用提示词文案掩盖缺口。

## 本文对应规则

本节配方落在图片阶段的 `IMG-...` 规则上，对应的本地错误码（`IM-`／`REF-`／`TXT-`）与落点见
[规则索引](rule-index.md)，逐条主旨：

- `IMG-01` — 先指向《视觉设定.md》中已接受的准确条目与当前变体，再写正文；不凭别名或
  外观相似猜绑定；
- `IMG-02` — 识别性身份、地理、尺度和当前状态优先；质量／风格词只能精炼这些事实，
  不能替代它们；
- `IMG-07` — 把文字政策解析成结构化选择；必须可读的文字与全局"不要文字"约束不能同时激活；
- `IMG-08` — 参考图进入制作前也要通过文字政策审查；审查对象是参考图里可辨文字、近似字形、
  号码、标牌、屏幕界面、水印与字幕残留，不是提示词有没有写"无文字"；
- `IMG-09` — 每张参考图只决定已经声明的内容；同时写明可以参考和不能照搬的可见事实，
  避免构图／尺度／效果参考改写身份、文字或故事状态；
- `IMG-12` — 每张真实参考图绑定一个稳定槽位，调整顺序不改变语义，换图在同一槽位显式修订路径；
- `IMG-14` — 槽位 `用途` 只能取封闭九词之一，一张图只答一个问题；资产板不用 `起始帧`／
  `结束帧`。

分级词（`structural`／`reviewed`／`craft`／`taste`）只作追溯锚点，判定依据是本文件正文；
上游编号与本地错误码的对应见 [规则索引](rule-index.md)。

## 从资产事实到画面语言

按下列四类选择当前图需要的事实：

| 类别 | 问题 | 写法 |
|---|---|---|
| 识别锚点 | 去掉服装/天气后，凭什么认出它 | 可见形状、比例、相对位置、材质特征 |
| 状态差异 | 这次与基准版本具体差在哪 | 有边界、能直接看到的变化 |
| 复用几何 | 后续镜头最怕哪里漂移 | 方位、尺度、入口、握持面、结构关系 |
| 呈现条件 | 怎样最利于读清以上事实 | 构图、视角、背景、光线、空场政策 |

抽象标签要翻译成证据。"冷峻"本身不够——在表情、站姿、服装线条或冷色环境里选与资产事实
相符的可见载体，但不得臆造伤疤、身份或剧情。

### 锚点选择启发

- **`craft_default`**：选少量、作用不重复的锚点。轮廓＋比例＋一个局部特征＋一个材质或色彩
  关系，通常比十个近义形容词更稳；
- **`reviewed_invariant`**：锚点必须足以让审查者区分该身份及所选版本，"漂亮、奢华、高清"
  不能代替识别证据；
- **`craft_default`**：空间用相对关系表达（"服务台在主入口右前方，后墙有唯一金属门"），
  比散列物件清单更可复用；
- **`taste_option`**：锚点可以用简洁技术文风或富有气氛的中文表达，只要不改变事实优先级。

## 八段式配方

顺序是信息保真策略，不是必须出现八个小标题的僵硬格式。省略不适用段，
**不省略类型必需事实**。

1. **用途与主体**：先说是人物设定图、场景空镜、道具参考还是局部修改，主体是谁。
2. **稳定锚点**：身份、地理或形制的持久事实，写可见、可比较的内容。
3. **版本差异**：只写这次造型、视角或状态相对基准版本的差异，以及当前状态。
4. **构图与尺度**：视角、画幅用途、主体占比、方向、相对位置、比例参照。
5. **材质、色彩与光线**：说明对识别有用的表面、主次色关系、光向和亮暗逻辑。
6. **背景/舞台政策**：干净背景、环境内展示或 `empty_stage`；是否允许人群、手或支架。
7. **文字与功能**：引用资产来源政策，再明确 `readable | symbolic | blank | postproduction`
   之一，并说明功能件怎样可见。
8. **排除与保留**：只写当前最可能出现的误读；局部修改先说明必须保留什么。

### 每段写多细：细节密度

八段式规定顺序，不规定每段写多细。第 2、3、5 段的密度按用途三选一：骨架级（远景识别、
群演、草图方向）、标准级（默认）、定妆级（主角定妆、跨集锁脸，逐件写到材质与五金）。
层序、受控词表、质量词三档政策、禁止项分组写法见 [细节密度](detail-density.md)。

**`craft_default`**：多视图板里身份层只写一遍，其余视图用一致性句要求复制；每块画面重写一遍
脸是四视图换脸的主要原因。

### 通用骨架

```text
[参考图类型与用途]，[主体与稳定身份/地理/形制锚点]；当前为[该版本的可见差异]。
采用[构图/视角/方向/尺度与空间关系]；[材质、色彩、光向和气氛]；[背景或空场政策]。
文字政策：[政策与精确要求]。保持[必要事实]；排除[与必需事实不冲突的高风险误读]。
```

这只是填写顺序，不是固定答案。删掉空项和机械标签，让成品像视觉部门能直接用的工作说明。

### 按产物类型裁剪

- `character_sheet`：身份锚点绑定一个造型版本，选便于识别的构图；没有文字承载面时
  删除文字字段。
- `look_state_variant`：绑定基础来源、可见变化和有效范围；姿势本身不自动成为新版本。
- `location_plate`：写清地理、方向和空场政策；标牌文字必须先有已接受的资产政策。
- `prop_plate`：同时交代轮廓、功能、尺度和适用的文字处理。
- `creature_plate`：形体、斑纹、配色一处一锚；重点锁五官/耳朵/尾巴的形制。
- `edit_delta`：只保留精确目标、变化、保持项和连续性影响；上游负责的变化先取得其接受。

## 可复制文体

- 用提示词语言（`format.prompt_language`，缺省中文）写自然表述；
- 密度按用途选级；渲染校准句（8K／PBR／SSS／浅景深）只放尾部一次，且在具体材质细节之后；
- 不写 JSON 键名、hash、审查指令、重试历史、"请模型务必"、权重语法、某家模型专用控制词；
- ID 与来源留在 Markdown 元信息里，不塞进正文；
- 正文可以分句，但离开内部资料后仍应读得懂；
- 不写"根据上图保持一致"却不点名是哪张图——要写就写 `REF-...` 槽位与它控制什么。

## 文字政策两层

文字有两层，不得混成一个枚举：

1. **资产来源政策（资产侧拥有）**：`exact_readable | graphic_only | no_readable_text |
   pending_creator_text`，回答剧情/资产真相是什么。
2. **本次提示词的呈现方法（提示词侧拥有）**：`readable | symbolic | blank |
   postproduction`，回答这张图怎样处理该真相。

条目必须指向《视觉设定.md》的准确条目与文字事实，并写清两层选择和理由。默认映射：

| 资产来源政策 | 允许的呈现方法 | 要求 |
|---|---|---|
| `exact_readable` | `readable` 或 `postproduction` | 前者逐字引用；后者保留承载区与精确文字引用 |
| `graphic_only` | `symbolic` | 保留图形存在/布局，不新造可辨字义 |
| `no_readable_text` | `blank` 或明确不可读的 `symbolic` | 不得偶然造成新名字/号码 |
| `pending_creator_text` | `postproduction`（`readable` 被阻断；不猜文字，保留 `unresolved` 与下游影响） | 先回资产侧补定文字，再按已接受政策重选呈现方法 |

需要超出映射时，先回资产侧按创作者选择修订来源政策，再据已接受政策选呈现方法；
本阶段不能保持原政策却自行放宽映射。

四种呈现方法的定义：

- `readable`：正文逐字引用已接受文字，并允许清晰可读；不要同时要求"不要文字"；
- `symbolic`：允许文字感图形，明确不要求可辨字义；
- `blank`：承载面保持空白；
- `postproduction`：预留干净区域与透视/光照条件，文字后期加入。

文字政策不是对模型效果的保证，而是创作与后期的工作要求。专名、号码或网址尚未被明确接受时
不要编造。

"语义上必须有签名"不等于已经拥有可复制的正式签名字形——只有签名归属或剧情职责、
没有创作者确认的字形资产时，保留准确来源说明并阻断 `readable`；仅在政策允许
`postproduction` 时预留承载区，不得用姓名、伪签名或自造笔画冒充正式字形。
若人物的接收或反转依赖这项文字，不得一面保留空白承载区、一面让人物认出签名；候选文本
明确写"正式签名字形未提供"，并点名受影响的 `IMG-...`／`SHOT-...`；在字形或已确认的后期处理
真正到位前，不写可读签名正文。

## 参考图也要过文字审查

文字政策同时管输出意图和输入参考图。只有创作者/权利人给出可核对的画面说明时，把状态
写为 `creator_described`；运行环境明确授权检查输入参考并完成检查时，写 `visually_inspected`，
此时才判断可辨文字、近似字形、号码、标牌、屏幕界面、水印和字幕残留——不能只检查提示词正文
有没有写"无文字"；只有文本记录、媒体不可见或未获授权时保持 `unverified`，不编造观察结论。

- `no_readable_text`：参考图仍带文字风险时，先**裁切、清理、遮罩或替换**；会破坏身份/地理/
  构图时，退回资产侧或改后期，不得靠更强的负面词假装风险消失；
- `exact_readable`：只允许批准的承载面与逐字内容；旧版本、冲突号码、其他标牌或字幕
  不能借参考图进入生成；
- `graphic_only`：允许的只是已接受的图形职责，不把偶然可辨的伪字当合格符号；
- 这一步只记录输入参考图的检查资料与文字风险；本阶段不生成或验收成片，也不从提示词
  声称文字已经正确渲染。

**`reviewed_invariant`**：审查者依据创作者或参考图权利人提供的画面说明，核对参考图、文字政策
与裁切／清理／遮罩／替换决定是否有来源、是否互相矛盾；没有检查资料时保持 `unresolved`。
"不要文字"这类负面提示**不能清除**参考图已经携带的字形、标牌、界面、水印或字幕残留。

## 参考图槽位

每张真实参考图用一个稳定 `REF-...` 槽位，逐字写成：

```text
REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）
```

槽位之外另行说明观察状态与未决风险。`IMG-...` 只定位当前《图片提示词.md》的提示词条目，
不表示一张真实图片。

`用途` 是封闭词表，只能取 **`身份／造型状态／地理／构图／尺度／效果／起始帧／结束帧／风格`**
之一。一张图承担两件事就拆成两个槽位，不写"全参考"，不自造新用途。参考说明不是普通图片
清单：每张只声明一个主要用途，分别写清可借用与不可带入的事实。

九词里除 `起始帧`、`结束帧` 属于镜头、**资产板不用**之外，其余七词都是资产板可用的用途。
参考声明是否合格要结合当前项目资料判断，不能按参考图数量、用途关键词或固定裁切方式机械判定。

- 身份参考不自动决定姿势、构图或临时造型；
- 构图/尺度参考只借用占比、机位所在一侧、留白或相对尺度，不带入图中人物与事件；
- 效果参考只控制已接受目标的形态/范围，不让非目标对象一起消失、复制或变形；
- 风格参考只借调性与笔触，不改身份、尺度与剧情状态；
- 任一参考都继续服从文字政策与已确认来源，冲突时退回负责方，不用"全参考"兜底。

调整顺序或插入新参考不能改变已有槽位的语义；换图时在同一槽位明确修订图片路径，不把旧图的
控制边界静默转给新槽位。没有参考媒体时写 `- 参考：无外部参考`；有参考却没有观察证据时
保持"未验证"并列出风险。

## 锚点与尺度

### 身份

身份锚点必须在临时状态改变后仍然成立。服装、淋湿、污渍、手持物和当下表情属于造型或状态，
而非身份；若"银灰短发"既可能是永久特征也可能是假发，先回资产侧解决，不在提示词里擅自定性。

### 场景地理

场景地理用固定入口、主要区块、视觉轴和锚点之间的关系表达。镜头角度变化不自动创造新地点，
提示词可以选一个视角，但不得为了"好看"搬动门窗。

空间纵深来自可通行路线、遮挡、重叠、尺度参照、光向和空气层次，前/中/后景是可选组织方法，
不是每条场景提示词必须填满的三栏；单房、平面化视觉方向或需要明确留白时可以不用。
资产场景参考图默认说明可复用地理，不把剧中盟友、敌人和当前动作提前摆进去；人物关系、
站位与视线由分镜关键帧在准确剧情状态下拥有。

### 尺度

尺度绑定同画面中的中性参照或明确尺寸关系，不写"巨大""小巧"；参照物不引入剧情角色，
不与 `empty_stage` 冲突；道具可用带刻度的底座、常见手掌尺度或已知功能结构作参照。

## 负面约束

- **`craft_default`**：负面约束针对可预见失败，如"不要混入第二套制服""空场，不出现演员"；
- 不要用"不要模糊、不要肢体错误、杰作"等套话覆盖真正的锚点；渲染校准句集中成尾部一句，
  见 [质量词三档](detail-density.md#六质量词三档)；
- 排除项不得否定必需项——要求旧铜锈又排除所有磨损、要求 `readable` 又全局禁字；
- **`reviewed_invariant`**：核对排除项是否会把人物特色、场景功能或道具使用方式一并抹掉。

## 审美语言

"电影感、质感、高级、氛围感"只有在落实为构图、材质、色彩关系、光向或景深选择时才有信息量。

- **`craft_default`**：每个审美词尽量落到一个可观察选择；删掉互换后不改变画面的近义词；
- **`craft_default`**：先建立清楚，再添加风格。参考板需要可比较性时，均匀光常优于戏剧光；
  但这是用途相关的默认，不是硬规则；
- **`taste_option`**：写实度、媒介、颗粒、色调和镜头感由视觉风格或创作者决定；
- 禁止用固定词表或形容词比例阻断交付；描述是否空泛，由审查者指出具体缺了什么。

## 光学与表面描述

**`craft_default`**：对需要明确透视或写实质感的画面，写明机位、取景距离和可见表面特征。
焦段可辅助表达，但不能据此承诺模型会精确模拟光学。

根据画面尺度选择毛孔、布料折痕或金属使用痕迹；"干净"不必等同于没有任何纹理和折痕。
不要给每张图添加相同的相机参数、瑕疵清单或排除词。

**`taste_option`**：表面是否平滑、是否修饰，以及写实程度由已接受的视觉风格决定。
结果用对照图检查；像素纹理指标只作辅助，不能代替人物与材质的视觉判断。

## 失败征兆

- 单看提示词无法分辨究竟是哪一个身份或版本；
- 锚点被风格套话淹没；临时伤势被写进永久面貌；
- 空间只有物品清单，没有方向/关系；尺度靠"很大"；
- `readable` 与全局"不要文字"同时存在；负面约束否定了主体；
- 参考图有与文字政策冲突的标牌、界面、号码、水印或字幕，却只在正文追加"不要文字"；
- 文案含用户抱怨、内部字段、生成次数、"根据上图保持一致"却没有目标引用；
- 出现 `--ar`、`(x:1.2)`、`cat::2` 一类引擎专用语法。

## 检查

默认在《图片提示词.md》写 `IMG-...` 条目，包含用途、准确视觉设定引用、参考字段与可复制正文；
必要的风险或修订说明留在正文外，不含媒体文件或远端任务信息。写完按四步核对：

1. **结构**：检查 ID、版本、类型必需字段、来源引用、参考图准入状态、来源政策到呈现方法
   的对应关系，以及可以直接确定的矛盾；
2. **内容**：审查者引用资产字段和提示词句子，判断身份、场景地理和尺度是否保持，
   不能只说"不够高级"；
3. **默认**：把泛化词提前、堆砌或重复视作可改进警告；只在必需事实缺失时才升级；
4. **选择**：风格和文体差异不单独阻断；记录创作者选择后，修订正文时继续保持。
