# 规则编号与检查器错误码

## 这张表解决什么

上游 `short-drama-assets` 用 `AST-*` / `CON-*` 编号陈述资产规则。本技能保留这些编号，是为了让
一条本地做法能追回它的上游依据，而不是把上游文档抄一遍。本表做三件事：

1. **查落点**：某个编号在本技能哪份文件、哪一节真正落地；
2. **查覆盖**：这条规则有没有被 `scripts/check_assets.py` 机械核对，还是只能人工判断；
3. **倒查**：检查器报出的错误码，对应哪条规则、该去改什么。

编号与分级只作追溯锚点，判断依据始终是本地各文件的正文。上游改了措辞不影响本技能的判定，
本地正文与上游冲突时以本地为准，并在资产说明里写明这处偏离。

## A. 上游编号 → 本技能落点

分级沿用上游：`structural` 阻断、`reviewed` 需证据、`craft` 可覆盖、`taste` 创作者选择。

| 编号 | 分级 | 说什么 | 本技能落点 | 机械核对 |
|---|---|---|---|---|
| `AST-01` | structural | 创建或复用资产前指向场景 ID 与可见证据 | [出项提取](documents-and-extraction.md#出项提取) | 否 |
| `AST-02` | reviewed | 每个出项归为 reuse／新身份／新变体／unresolved，不猜含混名或代词 | [身份与变体](identity-vs-variant.md#三个问题)、[称谓、代词与匿名对象](documents-and-extraction.md#称谓、代词与匿名对象) | 部分：`IM-03` |
| `AST-03` | craft | 分离 Character／Look、Location／View、Prop／State | 三份设计文档的「分工」节：[人物](character-and-look.md#分工)、[地点](location-and-view.md#分工)、[道具](prop-and-state.md#状态：此刻怎样) | 否 |
| `AST-04` | reviewed | 持久识别锚点与可变状态不混写 | [Character 最小识别集](character-and-look.md#character：最小稳定识别集)、[Location 边界](location-and-view.md#location-边界)、[状态：此刻怎样](prop-and-state.md#状态：此刻怎样) | 否 |

| `AST-06` | craft | 只跟踪识别、复用、提示词、连续性所需事实 | [出项不等于视觉资产](documents-and-extraction.md#出项不等于视觉资产) | 否 |

| `AST-11` | reviewed | 同批设计的角色不绑易混参考，各自命名可听区分特征 | [可选声音方向](character-and-look.md#可选声音方向：身份锚点不等于本场-delivery) | 否 |

| `AST-13` | structural | 提示词语言与条目标题语言不同时，每个被引用人物条目给出 `画面代称` 的精确拼写或 `画面代称：无` | [画面代称要覆盖每一种正文语言](character-and-look.md#画面代称要覆盖每一种正文语言) | 否 |
| `AST-14` | reviewed | 时代不与原著事实矛盾；旧／老式／复古一类词有原著依据或创作者选择 | [时代锚点](documents-and-extraction.md#时代锚点)、[语义审查](asset-review-checklist.md#b-语义审查（reviewed_invariant）) | 否 |

| `CON-03` | craft | 只跟踪下游相关变化，不是每镜整本设定集 | 同上 | 否 |

「部分」指检查器只覆盖该规则在本技能拥有的两份文件里的那一段，文档外的语义判断仍归人。`CON-07`
的下游一侧（分镜的冻结关键帧、视频提示词的 `MOTION-...`）不在本技能产出，也不在这里被核。

## B. 错误码 → 该去改什么

检查器只报字符串能证明的事。同一个码可能指向不同修法，按 `location` 列的行号回到原文看。

| 码 | 报什么 | 对应规则 | 怎么修 |
|---|---|---|---|
| `DOC-01` | 两份文件都找不到；或 `--partial` 之外缺提示词文件 | — | 检查路径；没写完提示词就加 `--partial` |
| `ID-02` | 《视觉设定.md》内条目 ID 重复，或提示词文件内 `IMG-` 重复 | `AST-10` | 同一身份只留一个 ID，重复的那条并入或改名 |
| `ID-03` | 同一专名《…》对应多个 ID | `AST-10` | 确认是不是同一个身份；是则合并，不是则改名区分 |
| `IM-01` | `IMG-` 条目缺 `资产／用途／视图／文字政策／参考` 之一 | `AST-05` | 补齐字段；确实不需要的写「无外部参考」等显式取值 |
| `IM-02` | `资产：` 没写出条目 ID，或指向视觉设定里不存在的条目 | `AST-05` | 填回真实存在的 `CHAR-`/`LOOK-`/`LOC-`/`VIEW-`/`PROP-`/`PSTATE-`/`CREA-` |
| `IM-03` | `资产：` 指向未决条目 | `AST-02` | 先在视觉设定里定下身份，或把该提示词标为被阻断 |
| `IM-04` | 没有以 `>` 开头的可复制正文 | `CON-07` 前置 | 正文必须是一段可直接复制的文字，不是列表或说明 |
| `IM-05` | 正文含引擎专用语法（`--ar`、`(x:1.2)`、`cat::2`） | 本地禁令 | 删掉，交给平台适配器 |
| `IM-06` | 正文含占位符 | 本地禁令 | 填实或删句 |
| `IM-07` | 正文混入内部字段或路径 | 本地禁令 | 只留画面语言，去掉 ID 之外的流程残留 |
| `LK-01` | 锁语法不完整；《中文名》不含中文；缺 `锁面：` | `CON-07` | 照 [语法](continuity-lock.md#语法) 补全整行 |
| `LK-02` | 锁 ID 重复声明 | `CON-07` | 一个实体一把锁，改 ID 或合并 |
| `LK-03` | 点名的 `IMG-` 无可复制正文，或锁面未逐字出现在正文里 | `CON-07` | 把锁面原样抄进正文；改写锁面的地方改回来 |
| `LK-04` | 锁面只出现在负面提示词里 | `CON-07` | 锁面必须写在描述画面内容的正面句里 |
| `LK-05` | 点名的 `IMG-...` 不在提示词文件里 | `CON-07` | 补条目，或从 `生图提示词项：` 里删掉 |
| `LK-06` | `镜头：` 范围解析不了（未知值、`入画` 与 `全集` 并存、与 `SHOT-` 混写、缺 `镜头：`）；或 `入画` 但所属条目与上层都没有 `来源：` | `CON-07`、`CON-04` | 改范围写法；`入画` 要写在能展开来源的条目下，否则改 `全集` 或写明确 `SHOT-...` |
| `REF-01` | `REF-` 数量与符合完整语法的条数不符 | 本地（REF 语法） | 照 [参考图槽位](prompt-recipe.md#参考图槽位) 补齐括号内三问 |
| `REF-02` | 用途不在封闭词表 | 本地 | 只用 `身份／造型状态／地理／构图／尺度／效果／起始帧／结束帧／风格` |
| `REF-03` | 资产板用了 `起始帧`／`结束帧` | 本地 | 那是分镜与视频的槽位，资产板不绑 |
| `REF-04` | 槽位或参考顺序号重复 | 本地 | 一槽一用途，重新编号 |
| `TXT-01` | 文字政策没写成 `来源政策 → 呈现方法`，或取值不在词表内 | 本地（两层政策） | 照 [文字政策两层](prompt-recipe.md#文字政策两层) 的固定映射写 |
| `TXT-02` | 映射不被允许；或 `no_readable_text` + `symbolic` 但正文没写明不可读 | `AST-05`、本地 | 换成许可的组合；用 `symbolic` 承担禁字时正文须显式说不可读 |
| `TXT-03` | 要求 `readable` 却正文全局禁字 | 本地 | 二者必须选一，不能同时要求 |

`LK-06` 的「`入画` 无可展开来源」以 `note` 报出，不计入错误，不影响退出码。

## B2. 本地规则（无上游编号）

| 编号 | 分级 | 说什么 | 落点 | 机械核对 |
|---|---|---|---|---|
| `DTL-01` | craft | 锚点密度按复用职责三选一（骨架/标准/定妆）；定妆级按 L1~L7 逐层写全；多视图里身份层只写一遍；渲染校准句只在尾部出现一次且在具体材质细节之后 | [细节密度](detail-density.md) | 否 |

`DTL-01` 是可覆盖的常用做法：创作者可以按平台实测结果加严或放宽，只需在交付说明里写明选择。

## C. 只能人工判断的部分

以下事项检查器结构上不可能替你判断，通过也不代表资产正确：

- 该不该复用、该不该建新变体（`AST-02`）、识别锚点是否够区分（`AST-04`）；
- 每把锁该不该上、锁面选得对不对、`镜头：` 范围是否覆盖它实际出现的所有镜头（`CON-07`）；
- 时代是否与原著一致、旧物的时代词是否有依据（`AST-14`、`AST-15`）；
- 连续性变化是否真有剧情原因、是否漏记了某条下游文档（`CON-02`、`CON-04`、`CON-06`）；
- 提示词语言与条目语言不同时该不该写 `画面代称`、代称拼写是否覆盖了正文里的每种写法
  （`AST-13`）——这条目前完全靠人工，按 [画面代称一节](character-and-look.md#画面代称要覆盖每一种正文语言) 逐条核；
- 正文是否真的写出了资产事实，而不是通顺却空泛的画面词。

人工判断的结论写进交付说明的末尾，不要因为检查器退出码是 0 就略过。
