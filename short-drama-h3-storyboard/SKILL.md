# 短剧 H3 参考分镜

把剧本事实、视觉设定和真实参考图编排成一次或多次可提交给 MiniMax H3 的生成单元。每个
`H3-UNIT-...` 是一份独立 job，内部可以包含一个或多个 `[Shot N]`，并最终给出可整体复制的 H3 正文。

## Quick Start

```text
用 $short-drama-h3-storyboard 把 EP001 的第 7 场拆成 H3 参考分镜和六段式提示词
```

## 使用边界

- 仅在本轮明确针对 `minimax-h3`，或现有项目档案已写 `target_video_model: minimax-h3` 时使用。
- 普通分镜、冻结关键帧或图片提示词请求仍走 `$short-drama-storyboard`；H3 视频提示词定稿仍可交给
  `$short-drama-video-prompts` 复核。
- 本技能不生成图片、视频或配音，不凭文件名声称图片存在，不改写剧情、人物身份或台词。
- H3 单元时长必须落在 4–15 秒。上游写了 16 秒或更长时，拆单元，不把超长时长硬塞进一次 job。
- 对白必须逐字来自《剧本.md》、已接受分镜或用户明确提供的文本。需要新台词时先回到写作阶段。
- 不覆盖通用《分镜.md》；默认输出 `剧集/<EP>/H3分镜.md`。

## 硬门禁

调用后先读取现有事实，只输出《H3 分镜参数确认卡》，然后停止。创作者确认前不得写最终文件、
不得调用生成服务、不得用“继续”代替确认。

确认卡至少包含：

```markdown
## H3 分镜参数确认卡
- 项目 / 剧集 / 场次：
- 目标模型：minimax-h3
- 输出文件：
- 原生时长约束：每个 H3-UNIT 4–15 秒
- 拟拆生成单元：
- 每个单元的 H3 模式：reference / first_frame / first_last_frame / base
- 参考图槽位与顺序：
- 主体映射：<Subject N> ↔ 角色 / 视觉设定 / <Picture N>
- 声线映射：角色 ↔ <Subject N> ↔ Sx
- 空间锁：屏幕左右、朝向、轴线、出入口、禁止镜像
- 台词来源：剧本场景 ID 与逐字文本
- 多镜容器门槛：每一刀是否都有已接受起始关键帧
- 待创作者决定：只列真正影响成稿的选择
```

## 工作流

1. 读取 `short-drama.json`、目标场次的《剧本.md》、《视觉设定.md》、已有《分镜.md》、
   《图片提示词.md》和项目中当前可读的参考图。只把真实存在的媒体写成 `REF-...`。
2. 先按叙事动作、对白长度、声音事件和 H3 的 4–15 秒上限划分生成单元。一个单元只承担一条清晰的
   `起点 → 主变化 → 终点` 状态链。
3. 决定 H3 模式：
   - 只有起始帧：`first_frame`；
   - 起始帧 + 结束帧：`first_last_frame`；
   - 角色、场景、道具或站位图与起始帧混用：`reference`；
   - 没有图且创作者明确选择文生视频：`base`。
4. 对每个可见主体分配 `<Subject N>`；按本次实际挂图顺序分配 `<Picture N>`；为每个说话人分配稳定
   `Sx`。主体 ID、图片 ID 和声线 ID 必须显式映射，不能靠数字巧合。
5. 先输出确认卡并停止。确认后，按“单元元数据 → 逐镜表 → H3 可复制正文 → 自检结果”的顺序成稿。
6. 用 `scripts/validate_h3_storyboard.py <成稿路径>` 做结构校验；有错误先修正再交付。
7. 汇报实际参考缺口、拆分后的单元数、总时长、多镜容器资格和仍需创作者决定的事项。

## 生成单元结构

~~~~markdown

- 时长：11 秒
- 模式：reference
- 来源：SC-EP001-007
- 参考图：REF-...（顺序：1）· ...（用途：身份；控制：...；不得控制：...）
- 主体映射：<Subject 1> = 师娘 = <Picture 1> = S1
- 声线映射：师娘 = <Subject 1> = S1 = ...
- 空间锁：...
- 口型纪律：...
- 状态链：... → ... → ...
- 声音：...

### SHOT-EP001-007A-01 · ...
- 职责：
- 起点：
- 唯一动作：
- 终点：
- 景别 / 机位 / 运镜：
- 声音 / 对白：

### H3 提示词
```text
subject_definitions: ...
summary: ...
retention_analysis: ...
detailed_description: [Shot 1] ...
overall_soundscape: ...
non_diegetic_music: N/A
```
~~~~

`H3 提示词` 是一次 job 的完整正文。`reference` 使用六段；`base`、`first_frame` 和
`first_last_frame` 使用 `integrated_multimodal_description`、`overall_soundscape`、
`non_diegetic_music` 三段。不要把六段拆成六次生成。

## 参考图怎么分工

沿用项目现有 `用途` 枚举。用户所说的“站位参考帧”归入 `用途：构图`，在 `控制` 里明确写
屏幕左右、轴线、入口方向和禁止镜像；不另造一套用途字段。

- `身份`：脸型、发型剪影、体型、比例、固定服装。
- `造型状态`：当前服装层叠、妆容、损污、发饰或配饰状态。
- `地理`：场景布局、固定家具、光源方向和色彩。
- `构图`：起始框取景、屏幕方向、站住位置、轴线、禁止镜像。
- `起始帧`：本 H3 单元第一格的构图和姿态。
- `结束帧`：已接受终态，只能在同时有起始帧时使用。

每张参考图只承担它在 `用途` 和 `控制` 中声明的事情。角色图不决定站位，场景图不决定脸，
站位图不决定人物身份。

## H3 正文规则

- `subject_definitions`：定义每个 `<Subject N>`、每个 `<Picture N>` 的角色，以及图中必须保留的
  可见特征。写法使用 `<Subject 1> is ... in <Picture 2>, with ...`。
- `summary`：一句话写本单元的可见状态变化，不写空泛情绪结论。
- `retention_analysis`：逐条写标签、出现镜次和保留强度。视觉素材使用 `fully_preserved`、
  `partially_preserved`、`attribute_transfer` 或 `weak_reference`。站位图必须写明屏幕布置、
  轴线和禁止镜像被保留。
- `detailed_description`：逐镜写 `[Shot 1]`、`[Shot 2] At 00:03.500, ...`。每个后续切点都有实际
  时间戳，台词跟说话人的可见动作放在同一事件里。
- `overall_soundscape`：只写环境声、物理音效和非语言人声，不重复对白事件。
- `non_diegetic_music`：没有非画内配乐时写 `N/A`。不要留空让模型补乐。
- 中文对白只写在 `<d>[Chinese] 逐字台词</d>` 内；语速、音色、画内或画外状态写在标签外。
- 把“无字幕、无水印、禁止换位、禁止手脸融合”等约束折进实际对应的段落，不另开 H3 不认识的字段。
  只保留针对本镜真实风险的约束，不用一长串通用负面词。

## 多人、口型与空间连续

- 所有说话人使用项目内稳定的 `Sx`。角色第一次说话时写清画内/画外和音色；同一项目后续单元
  继续使用同一 ID 和同一声音描述。
- 只有说话者可以动嘴。其他角色，包括同框正脸角色，必须明确写嘴部闭合且静止。
- 无对白双人镜写清两人嘴都闭合，不把“没有台词”留给模型猜。
- 写作前锁定屏幕左/右、人物朝向、视线、轴线、进入和退出路径。需要站位锁时写明
  `do not mirror <Picture N>`，并禁止跨轴、交换屏幕位置或位置跳变。
- 同框角色较多时写身高顺序、距离层级、谁在前景/背景，以及每个人在本刀内是否移动。
- 手、发簪、戒指、杯具等关键道具在相邻镜头中保持形制、持有人和轨迹连续。

## 对白、时长与多镜容器

- 先估完整发声时间，再决定单元时长；不通过加快语速塞台词。
- 一个 H3 单元推荐只装一个主要动作。把多个相邻镜头装进同一次生成时，只有每一刀都有已接受的
  起始关键帧才资格成立；否则逐镜生成。
- 多镜容器的时间戳严格递增并落在单元时长内。容器总时长仍受 4–15 秒限制。
- 台词与口型同轨的判断不是模型保证；生成后仍要核听逐字文本、停顿、尾音和口型落点。

## 完成与修订

完成后的 H3 分镜必须同时满足：

- 每个生成单元有唯一状态链、合法时长、明确模式和完整 H3 正文；
- 每个 `<Subject N>`、`<Picture N>`、`Sx` 都有唯一定义且跨单元一致；
- 每个引用图都有 `顺序`、中文名称、`用途`、`控制` 和 `不得控制`；
- 每句台词可追溯到来源；无对白镜明确嘴部状态；
- 站位、轴线、屏幕左右、持物和造型状态与相邻单元连续；
- 结构校验通过，未决真实缺口在末尾逐项说明。

修订时保留未受影响的 `H3-UNIT-...` 和 `SHOT-...` ID。拆分、合并或改参考图后，明确哪些下游
job 需要重新生成。不要顺手重写未点名的通用《分镜.md》。
